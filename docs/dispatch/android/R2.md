- Wave: 1 (parallel with UI-D, R1a, R1b-1, C1)

- Branch/worktree: `feat/android-r2-bootstrap`

## Goal

Make the app start and keep state correctly on an embedded (Android) build: a file-backed secret store behind the existing `SecretStore` and `KeyStore` traits, startup configuration of libgit2 (global config dir, owner validation, CA location), AI HTTPS without the JVM-bound platform verifier, and `git_path` settings that are inert without a git CLI. Call sites (`Arc::new(Keychain)`, `SystemKeys`) must not change, and desktop behavior must be identical.

## Owned files

Create: `src-tauri/src/secrets.rs` (+ tests inside or `secrets/tests.rs`), `src-tauri/src/mobile.rs` (embedded startup).
Modify: `src-tauri/src/lib.rs` (module declarations + `setup` hook only), `src-tauri/src/git/remote/keychain.rs`, `src-tauri/src/ai/settings.rs`, `src-tauri/src/ai/provider.rs` (`build_client` only), `src-tauri/src/settings/mod.rs`, `src-tauri/src/commands/settings.rs`.

Must NOT touch: `Cargo.toml`/`Cargo.lock` (webpki-roots is already a dependency for all targets; report if you need anything else), `src-tauri/src/ipc/**`, `src-tauri/src/platform.rs`, `git/remote/{net,ops,creds,validate,native,mod,tests}.rs` (R1a), `git/cli/**` (R1b-1), `src-tauri/tauri*.json`, frontend.

## Contracts

```rust
// src-tauri/src/secrets.rs (always compiled and host-tested)
pub struct FileStore { /* path, Mutex */ }
impl FileStore {
    pub fn new(path: PathBuf) -> Self;                          // file need not exist yet
    pub fn get(&self, service: &str, account: &str) -> Option<String>;
    pub fn set(&self, service: &str, account: &str, secret: &str) -> AppResult<()>;
    pub fn delete(&self, service: &str, account: &str) -> AppResult<()>; // missing is Ok
}
// JSON object { "<service>:<account>": "<secret>" } in BTreeMap order, written with
// settings::atomic_write, file mode 0600 on unix (set before rename), never logged.
impl crate::git::remote::keychain::SecretStore for FileStore   // service keychain::SERVICE, account keychain::account(host, user)
impl crate::ai::settings::KeyStore for FileStore               // same service/account naming the keyring impl uses
pub fn init(dir: &Path) -> AppResult<()>;                      // global OnceLock<FileStore> at <dir>/secrets.json; idempotent
pub fn global() -> Option<&'static FileStore>;

// src-tauri/src/mobile.rs, compiled only #[cfg(embedded_git)]
pub fn init(data_dir: &Path) -> AppResult<()>;
// create_dir_all(data_dir); secrets::init(data_dir);
// unsafe git2::opts::set_search_path(ConfigLevel::Global, data_dir)  (and XDG -> data_dir)
// unsafe git2::opts::set_verify_owner_validation(false)
// #[cfg(target_os = "android")]: point libgit2/OpenSSL at /system/etc/security/cacerts
//   (git2 0.21 API: check docs.rs for set_ssl_cert_dir / set_ssl_cert_file; these only exist with the
//    `https` feature, which only Android has, so keep them under cfg(target_os = "android")).
```

- `keychain.rs`: `impl SecretStore for Keychain` and `Keychain::available()` split into `#[cfg(not(embedded_git))]` (current keyring code, unchanged) and `#[cfg(embedded_git)]` (delegate to `secrets::global()`; `available()` is `global().is_some()`; `set` without init returns `ErrorKind::Internal` "secret store not initialised"; `get` returns `None`). All `keyring::` uses end up behind `cfg(not(embedded_git))` so Android never references the crate.
- `ai/settings.rs`: same split for `SystemKeys`.
- `ai/provider.rs::build_client`: under `#[cfg(embedded_git)]` build a `rustls::ClientConfig` from `webpki_roots::TLS_SERVER_ROOTS` with the ring provider already installed by this function and pass it through `reqwest::ClientBuilder::use_preconfigured_tls`, keeping the same timeouts; desktop branch unchanged. This keeps `rustls-platform-verifier` (which needs JVM init on Android) from ever being constructed.
- `settings`: under `EMBEDDED`, `git_path` is never validated or applied (no `Command::new`), is stored as given, and `settings_get` returns it untouched. Desktop unchanged.
- `lib.rs`: `pub mod secrets;`, `#[cfg(embedded_git)] pub mod mobile;`; in `.setup`, under `#[cfg(embedded_git)]`, resolve `app.path().app_data_dir()?` and call `mobile::init(&dir)?` before `mount_events`. Nothing else changes (R0 already gated the debug bindings export).

## Steps

1. `secrets.rs` with tests: round trip, overwrite, delete missing, two services do not collide, file mode is 0600 (unix), atomic write leaves no temp file, corrupt file => `get` None and `set` rewrites cleanly, concurrency (two threads setting different keys both persist).
2. Keychain / SystemKeys cfg split; make sure both `cargo clippy` variants are warning-free (dead code under one cfg is a common trap).
3. `mobile.rs` and lib.rs setup; unit-test what is testable on the host (dir creation, global config path: after `init(tmp)`, `git2::Config::find_global()` resolves under `tmp`). Tests that change libgit2 global options must be serialized and must restore state, or run in a dedicated `#[ignore]`-free test binary module guarded by a mutex; never leak the changed search path into other tests.
4. `build_client` TLS branch; test under `--features embedded-git` that the client builds and that an HTTP mockito call still works.
5. Settings behavior under embedded; tests for both cfgs.
6. Read-only check: confirm `GitState::ensure_watcher` degrades silently if `notify` fails (report; do not edit `git/`).
7. Commits: `feat(android): add file-backed secret store for embedded builds`, `feat(android): initialise libgit2 and TLS for embedded builds`, `feat(settings): ignore git path without a git CLI`.

- Under `--features embedded-git`: `Keychain` and `SystemKeys` persist through `FileStore` after `secrets::init`, with no call-site changes; all listed tests green.
- Secrets file is 0600, written atomically, never printed (grep your code for `println!`/`log` of secret values: none).
- `build_client` under embedded uses the preconfigured webpki-roots TLS config.
- `git_path` ignored under embedded (test).
