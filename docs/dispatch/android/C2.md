## Goal

Ship the Android APK as a release asset signed with the maintainers' key, keep the embedded (Android) Rust paths tested on every push via host CI, require the Android build on PRs into `main`, and document building, releasing and the Android limitations.

## Owned files

Modify: `.github/workflows/release.yml`, `.github/workflows/ci.yml`, `.github/rulesets/main-protection.json`, `scripts/check-version.mjs` (+ new `scripts/check-version.test.mjs`), `docs/BUILD.md`, `docs/RELEASING.md`, and (delegated by the orchestrator for this task) `README.md` and `docs/ARCHITECTURE.md`.

## Requirements

### `release.yml` (ANDROID_PLAN §4.1, with these decisions)

- `verify`: the loop `for wf in ci.yml build-windows.yml` becomes `for wf in ci.yml build-windows.yml build-android.yml`; update step name ("CI, Build Windows and Build Android must have passed for this commit"), error text and header comment.
- New job `android`, **named `Android release APK`** (distinct from the PR check context `Android APK`), `needs: [verify, build]`, `if: needs.build.result == 'success'`, `runs-on: ubuntu-24.04`, `timeout-minutes: 90`; checkout at `needs.verify.outputs.sha`; `uses: ./.github/actions/build-android` with `abis: aarch64,armv7,x86_64`, `sign: release` and the four `ANDROID_*` secrets as inputs; then `gh release upload "v$VERSION" "<apk-path output>" --repo "$GITHUB_REPOSITORY" --clobber`.
- Missing secrets: hard fail of the Android leg with a clear `::error::` naming the missing secret names (the action already does this; do not duplicate secret values anywhere). Desktop legs are unaffected, but `publish` will not run: document this.
- `publish`: `needs: [verify, build, android]`, `if: needs.build.result == 'success' && needs.android.result == 'success'`; add `'_android-universal\.apk$'` to the asset patterns.
- `scripts/check-version.mjs`: additionally fail if minor or patch >= 1000 (Tauri's derived Android `versionCode` is `major*1000000 + minor*1000 + patch`), with an explanatory message.

### `ci.yml`

In the `checks` job, Linux leg only, after the existing `cargo test` steps: `cargo clippy --all-targets --features embedded-git -- -D warnings` and `cargo test --features embedded-git` (working-directory `src-tauri`, `if: runner.os == 'Linux'`). No other change.

### Ruleset

Add `{ "context": "Android APK", "integration_id": 15368 }` after `"build"` in `required_status_checks`. Keep formatting consistent with the file.

### Docs

- `docs/BUILD.md` "Building for Android": JDK 17, Android SDK + NDK, `ANDROID_HOME`/`NDK_HOME`, `rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`, `pnpm tauri android dev`, `pnpm tauri android build --apk --target aarch64`, the committed `src-tauri/gen/android` + `node scripts/android/customize.mjs` + the `android-init` workflow for regeneration, `cargo test --features embedded-git` as the host stand-in, sideloading, and the throwaway-key notice for CI APKs (uninstall before installing another CI build).
- `docs/RELEASING.md`: the four secrets (`ANDROID_KEYSTORE` base64 single line, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`), `keytool` command, key custody (losing it means users can never update), the verify gate now includes Build Android, the new asset, and the "missing secrets blocks publish" behavior; suggest an `android-release` environment.
- `README.md`: Android section (sideload APK, HTTPS + personal access token only, no SSH, repositories live in app storage and are cloned in-app, secrets stored in an app-private file (0600) rather than a keystore in v1, feature differences: no hooks/signing/interactive rebase/submodule update).
- `docs/ARCHITECTURE.md`: embedded git backend (`cfg(embedded_git)`, `GitCli` shim, native network layer, `FileStore` secrets, `platform_info` capabilities vs `useLayout` layout), mobile shell and navigation store, in the existing tables/sections style.
