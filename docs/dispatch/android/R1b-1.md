## Goal

When `cfg(embedded_git)` is set, every `GitCli` invocation is served in-process by a libgit2 "shim" that speaks the exact CLI dialect the codebase uses and returns a `CliOutput` shaped like git's (exit code, stdout, stderr), so the ~15 call sites and their parsing work unchanged on Android. This package covers commit, stash, merge, cherry-pick, revert, sequencer control, switch, add/rm and reset; rebase, worktree and `log --follow` are stubs owned by R1b-2.

## Owned files

Modify: `src-tauri/src/git/cli/mod.rs` (the `embedded` flag, the dispatch, and the `Unsupported` mapping in `CliOutput::into_result`; nothing else), `src-tauri/src/git/cli/tests.rs`.
Create: `src-tauri/src/git/cli/embedded/{mod.rs, commit.rs, stash.rs, merge.rs, pick.rs, sequencer.rs, conflicts.rs, switch.rs, reset.rs, rebase.rs (stub), worktree.rs (stub), log.rs (stub)}` and `src-tauri/src/git/cli/embedded/tests.rs`.
Annotation-only (add `#[cfg(not(embedded_git))]` to tests that need CLI-only behavior: hooks, signing, interactive rebase, worktrees, file history, submodules, rebase until R1b-2): `src-tauri/src/git/{history,staging,stash_write,advanced,conflicts}/tests.rs`, `src-tauri/src/git/crlf_tests.rs`, and test modules under `src-tauri/src/ai/plan*`. Never change a test's body or assertions; if a test fails under embedded for a reason you believe is a shim bug, fix the shim.

## Contract

- `GitCli` gets a private `embedded: bool` = `cfg!(embedded_git)` in `new()`, preserved by `with_path` and `Default`. `run_streaming` (the choke point used by `run`, `run_read`, `run_raw`) starts with `if self.embedded { return embedded::run(dir, &args, opts, op, on_stderr); }` (adapt to the real signature). Nothing else in `GitCli` changes behavior.
- `embedded::run` parses the subcommand and flags and dispatches to handlers built on `git2`. Unknown subcommands or flags return `CliOutput { code: 1, stderr: "error: unsupported on this platform: git <cmd> ..." }`; the caller path must end up as `ErrorKind::Unsupported` (if callers map exit 1 to `GitCli`, add the mapping in `CliOutput::into_result` for that exact stderr prefix, which is in your file).
- Global options the call sites pass (`-c key=value`, `--no-pager`, `-C`) must be accepted and applied or ignored explicitly. Env such as `GIT_SEQUENCE_EDITOR`, `GIT_EDITOR`, `GIT_TERMINAL_PROMPT` is ignored. Stdin from `CliOptions` feeds `commit -F -`.
- Dialect to support (grep every `GitCli`/`run_git`/`run_raw` call site to confirm and complete this list; the call-site file list is in ANDROID_PLAN §1.4):
  - `commit -F - [--amend] [--allow-empty] [--no-verify] [--signoff]`, `commit --no-edit` (conclude a merge / cherry-pick): tree from index, parents from HEAD (+ MERGE_HEAD), author/committer from `repo.signature()`; hooks skipped; if `commit.gpgsign=true`, commit unsigned and print a warning on stderr; clean up merge/cherry-pick state after a successful conclude.
  - `stash push [--include-untracked] [--keep-index] [-m <msg>] [-- <paths>]`, `stash store -m <msg> <oid>`, `stash apply|pop <stash@{n}>`, `stash drop <stash@{n}>`: libgit2 stash API; apply conflicts => exit 1 and git-like stderr.
  - `merge --no-edit [--no-ff|--ff-only] [-m <msg>] <rev>`, `merge --abort`: fast-forward via checkout + ref update (`--ff-only` fails with git's "Not possible to fast-forward, aborting." exit 128); otherwise `repo.merge` + commit when clean; on conflicts leave `MERGE_HEAD`/`MERGE_MSG` and a conflicted index, print `CONFLICT (content): Merge conflict in <path>` lines and `Automatic merge failed; fix conflicts and then commit the result.`, exit 1. R1a's pull uses exactly `["merge","--no-edit","-m",<msg>,<oid>]` and `["merge","--no-edit","--ff-only",<oid>]`.
  - `cherry-pick [--no-edit] <commits...>`, `revert [--no-edit] <commits...>`, and `--continue | --abort | --skip` for both: apply commits in order; on conflict stop with state (`CHERRY_PICK_HEAD`/`REVERT_HEAD`, and for multi-commit sequences a `.git/sequencer/todo` in git's format so `repo.state()` reports the `*Sequence` variant), exit 1 with git-like messages.
  - `reset --merge` (sequencer abort for merges) and any other `reset` forms found at call sites.
  - `switch <branch>`: safe checkout of the branch tree + `set_head`; refuse on conflicting local changes with git's message, exit 1.
  - `add -- <path>`, `rm --quiet -f -- <path>` (conflict resolution).
  - `rebase ...`, `worktree ...`, `log --follow ...`: stubs in `rebase.rs`, `worktree.rs`, `log.rs` returning the unsupported result (R1b-2 replaces the bodies; keep a single `pub fn run(ctx, args) -> AppResult<CliOutput>` per file so R1b-2 does not need to touch `mod.rs`).
  - Network subcommands (`fetch`, `push`, `pull`, `clone`, `ls-remote`) and `submodule`: unsupported (R1a handles network natively before reaching the CLI).
- Exit codes: 0 success, 1 conflicts / refused operation, 128 fatal (bad revision, not a repo, ff impossible), mirroring git; stdout/stderr text that callers parse must match git's wording.

## Acceptance criteria

- Desktop: `GitCli` behavior unchanged; full desktop suite green.
- Embedded: full suite green except `git::remote` (which the checker runs after merging R1a); annotations limited to genuinely CLI-only behavior (hooks, signing, interactive rebase, rebase, worktrees, `log --follow`, submodules).
- Conflict paths of merge / cherry-pick / revert / stash apply produce the same `OpOutcome` values as on desktop (same tests pass).
- Unsupported commands surface as `ErrorKind::Unsupported`, not a panic or `Internal`.

## Out of scope / needs orchestrator

Rebase, worktrees, `log --follow` (R1b-2). Network (R1a). Any contract change.
