## 1. Known repositories (`git/recent.rs`, `commands/repo.rs`)

- Keep `recent-repos.json` and `MAX_RECENT = 20` exactly as they are (`repo_recent` is unchanged).
- Add `known-repos.json` in the same directory, `pub const MAX_KNOWN: usize = 500`, same atomic write and the same `WRITE_LOCK`.
- `record()` also upserts the path into the known list (name and `last_opened` updated). When the known list exceeds 500, drop the entries with the oldest `last_opened`.
- `pub fn known(&self) -> Vec<KnownRepo>`: reads the known file; when it does not exist yet, seeds it from the recent list and saves it; also merges recent entries that are missing (old installs). Sets `exists = Path::new(&path).exists()`. Sorted by name case-insensitively, then path. A corrupt file reads as empty (then reseeded from recent).
- `pub fn forget(&self, path: &str) -> AppResult<()>`: removes the exact path from both files; never touches the disk folder. Unknown path: `Ok(())`.
- `remove_path()` (used by `repo_delete`) also prunes the known list.
- Commands: `repo_known` runs `known()` on `blocking` (it stats every path) and returns `Ok(vec![])` when there is no app data dir; `repo_forget` calls `forget`.
- Tests (in `recent.rs`): seeding from recent; record adds to known beyond 20 entries; cap at 500; forget removes from both; `exists` false for a missing folder; sort order; corrupt known file.

## 2. `app_open_url` (`commands/app.rs`)

```rust
pub const OPEN_URL_HOSTS: &[&str] = &["github.com", "gitlab.com", "bitbucket.org"];
/// The URL if it is safe to hand to the system browser.
pub fn validate_open_url(url: &str) -> AppResult<reqwest::Url>
```

Rules: at most 2048 characters; parses with `reqwest::Url`; scheme exactly `https`; no username or password; host (lower-cased) exactly one of `OPEN_URL_HOSTS` (no subdomains, no IP, no port other than none/443). Anything else: `InvalidInput` "Only https links to GitHub, GitLab or Bitbucket can be opened". The command validates, then opens with `tauri_plugin_opener::OpenerExt`: `app.opener().open_url(url.as_str(), None::<&str>)`, mapping the error to `ErrorKind::Io` with a message that contains no URL query string. Unit tests for the validator: accepts `https://github.com/a/b/pull/1`, `https://gitlab.com/-/user_settings/ssh_keys`; rejects `http://github.com`, `javascript:alert(1)`, `file:///etc/passwd`, `https://user:pw@github.com/`, `https://github.com.evil.com/`, `https://evil.com/?u=https://github.com`, `https://api.github.com/`, `https://github.com:8443/`, a 3000-character URL.

## 3. Workspaces validation (`settings/mod.rs`)

Inside `validate()` (before the `EMBEDDED` early return, so it applies everywhere), normalize and check `workspaces`:

- at most 50 workspaces; `id` 1-64 chars of `[A-Za-z0-9_-]`, unique; `name` trimmed, 1-64 characters;
- each workspace at most 200 repos; each path non-empty after trim, at most 4096 chars, no NUL; duplicate paths removed keeping the first occurrence;
- error kind `InvalidInput` with a message naming the problem (e.g. "A workspace name must be 1 to 64 characters").
  Tests in `settings/tests.rs` for each rule, plus a round trip through `save`/`load`.

## 4. Pull requests (`forge/mod.rs`, `forge/github.rs`, `commands/forge.rs`)

Extend the `Forge` trait (same boxed-future style):

```rust
fn list_pulls<'a>(&'a self, q: &'a PullQuery) -> BoxFuture<'a, AppResult<PullPage>>;
fn pull<'a>(&'a self, number: u32) -> BoxFuture<'a, AppResult<PullDetail>>;
fn comment_pull<'a>(&'a self, number: u32, body: &'a str) -> BoxFuture<'a, AppResult<ForgeComment>>;
```

`GithubForge`:

- `list_pulls`: `GET repos/{o}/{n}/pulls?state=<open|closed|all>&per_page=<1..=100>&page=<>=1>&sort=updated&direction=desc`; `next_page` from the `Link` header (existing `next_page`).
- `pull_of(v)`: `number`, `title`, `state` = `Merged` when `merged_at` is a non-null string, else `Closed` when `state == "closed"`, else `Open`; `draft` (missing = false); `author` from `user.login` (existing `user_of`); `labels` (as for issues); `created_at`/`updated_at` via `parse_time`; `url` = `html_url`. `head`/`base` from `{ ref, label, sha, repo: { full_name } | null }`; `is_fork` = head repo full name differs from base repo full name, or head repo is null.
- `pull`: `GET pulls/{n}`, then conversation comments via the existing `comment_pages("issues/{n}/comments", Scope::Repo)`; `body` null becomes `""`; `commits`, `additions`, `deletions`, `changed_files` (u64 clamped to u32, missing = 0); `mergeable` (`null` = None).
- `comment_pull`: `post_comment("issues/{n}/comments", body, Scope::Repo)` (requires a token, same validation as issue comments).
- Commands use `forge::github_for(&state, &repo)` like the issue commands. The "Issues need a GitHub remote" message in `github_for` may become "This needs a GitHub remote" (keep the `Unsupported` kind).

## 5. Notifications (`forge/notifications.rs`, `commands/forge.rs`)

```rust
/// Unread notification threads of the token's user.
pub async fn list(client: &reqwest::Client, api: &str, token: Option<&str>) -> AppResult<Vec<ForgeNotification>>;
/// Web page for a notification subject, always under https://github.com/.
pub fn web_url(subject_url: Option<&str>, subject_type: &str, repo_full_name: &str) -> Option<String>;
```

- No token: `AuthRequired` "Add a GitHub token in Settings > Integrations to see GitHub notifications", without any network call.
- `GET {api}/notifications?per_page=50` with the same headers as other GitHub calls (make `authed`, `error_for`, `network` `pub(crate)` in `github.rs` rather than copying them).
- 401 → `AuthFailed` "GitHub rejected the token"; 403 → `Unsupported` "This token cannot read notifications. Use a classic token with the notifications scope." (fine-grained tokens get 403 here); other errors through `error_for`.
- Mapping: `id` (string), `subject.title`, `subject.type` → `kind`, `reason`, `repository.full_name`, `unread`, `updated_at` (`parse_time`), `url = web_url(subject.url, subject.type, repository.full_name)`.
- `web_url` uses the path after `/repos/{owner}/{name}/` of the subject API URL, whatever the API host: `pulls/{n}` → `https://github.com/{o}/{r}/pull/{n}`, `issues/{n}` → `.../issues/{n}`, `commits/{sha}` → `.../commit/{sha}`; anything else (releases, discussions, `None`) → `https://github.com/{repo_full_name}`. Owner, name, number and sha are validated (`[A-Za-z0-9._-]`, digits, hex) and otherwise yield the repository page. Result is always `https://github.com/...` so `app_open_url` accepts it.
- Command `forge_notifications(host)`: `host != "github.com"` → `Unsupported` "Notifications are only available for github.com"; token from `tokens::resolve(&SystemTokens, &Keychain, &host).0`; client `crate::http::client(github::TIMEOUT)?`; `list(&client, github::API_BASE, token.as_deref())`.

## 6. SSH keys (`ssh/mod.rs`, `ssh/tests.rs`, `commands/ssh.rs`)

The module is compiled only off Android (`lib.rs` already has the cfg). Use `ssh-key` 0.6 (`ssh_key::{PrivateKey, PublicKey, HashAlg, LineEnding, Algorithm}`, `ssh_key::rand_core::OsRng`).

```rust
pub fn ssh_dir(home: &Path) -> PathBuf;                       // home/.ssh
pub fn validate_name(name: &str) -> AppResult<()>;            // ^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$ and not ending in ".pub"
pub fn list(dir: &Path) -> AppResult<Vec<SshKey>>;            // missing dir -> Ok(vec![])
pub fn generate(dir: &Path, req: &SshKeyGenerateRequest) -> AppResult<SshKey>;
```

- `list`: every regular file `*.pub` up to 16 KiB in `dir`; parse the first non-empty line with `PublicKey::from_openssh`; skip files that do not parse. `name` = file stem, `path` = `dir/<stem>`, `public_key` = the trimmed line, `algorithm` = `pk.algorithm().as_str()`, `fingerprint` = `pk.fingerprint(HashAlg::Sha256).to_string()`, `comment` = `pk.comment()`, `has_private_key` = `dir/<stem>` is a file. **Never open private key files.** Sorted by name.
- `generate`: `validate_name`; comment at most 256 chars without control characters; passphrase at most 1024 chars; create `dir` if missing (mode 0700 on unix); if `dir/<name>` or `dir/<name>.pub` exists → `InvalidInput` "A key named <name> already exists"; create an ed25519 key with `OsRng` and the comment; if the passphrase is non-empty, `encrypt(&mut OsRng, passphrase)`; write the private key (`to_openssh(LineEnding::LF)`) with `crate::settings::atomic_write_mode(path, bytes, Some(0o600))` and the public key line + `\n` with mode `0o644`; return the entry `list` would produce for it.
- Commands: home from `app.path().home_dir()` (error → `Io` "No home directory"); run on `blocking`; `ssh_keys_list` returns `SshKeyList { dir, keys }`. On Android (`#[cfg(target_os = "android")]` branch inside each command) return `Unsupported` "SSH keys are not available on this device".
- Tests (`tempfile`): generate unencrypted, then list shows it with `ssh-ed25519`, `SHA256:` fingerprint, the comment and `has_private_key`; private file mode is 0600 on unix; encrypted generation: `PrivateKey::from_openssh(file)?.is_encrypted()` is true and decrypts with the passphrase; refusing to overwrite; invalid names (`""`, `../x`, `a/b`, `.hidden`, `x.pub`, 65 chars); an unparsable `.pub` is skipped; a `.pub` without its private key has `has_private_key == false`; missing dir lists empty.
